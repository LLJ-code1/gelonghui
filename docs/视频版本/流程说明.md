# 视频版本：Fanbook 视频保存与内容整理流程

## 触发词

当用户说以下任一句时，默认启动视频保存流程：

- `保存最新视频`
- `跑一轮视频保存`
- `保存格隆汇视频`

当用户说以下任一句时，默认启动完整视频内容整理流程，但执行前必须先复述流程并等用户确认：

- `跑一下最新的视频`

这里的“视频”指 Fanbook `#视频` 频道里的网盘分享，不是 `圈子/最新` 观点流。`保存最新视频` 只处理网盘保存；`跑一下最新的视频` 默认处理“保存 -> 下载 -> 转写 -> 观点整理 -> 画面复核”。

## 交互确认规则

当用户说 `跑一下最新的视频` 时，不要直接开始访问 Fanbook 或夸克，先回复本轮准备执行的流程：

```text
我准备跑视频版完整流程：
1. 读取 state/video_checkpoint.json，确认上一轮断点。
2. 打开 Fanbook #视频，从顶部扫到上一轮断点。
3. 识别新增夸克视频链接，保存到夸克 全部文件/格隆汇/YY.M.DD。
4. 下载视频到 data/video_files/YYYY-MM-DD/。
5. 用 faster-whisper medium 转写。
6. 生成音频观点整理、画面复核候选、抽帧复核结果和视频观点整理稿。
7. 所有输出按 YYYY-MM-DD 归档，不在 docs 或根目录散落单视频文件。

请确认是否开始。
```

只有用户确认后，才进入实际执行。若用户只要求“保存最新视频”，则只走网盘保存流程，不默认下载和转写。

## 固定入口

```text
https://web.fanbook.cn/channels/887510463079116800/887585348161761280
```

## 默认目标目录

夸克网盘：

```text
全部文件/格隆汇/YY.M.DD
```

示例：`2026-05-24` 对应 `全部文件/格隆汇/26.5.24`。

本地视频文件：

```text
data/video_files/YYYY-MM-DD/
```

本地视频文件体积较大，`data/video_files/` 默认不进入 Git；只追踪下载索引 `data/video_downloads/YYYY-MM-DD.jsonl`。

## 日期归档规范

视频版本所有运行产物按实际处理日期 `YYYY-MM-DD` 归档。不要在仓库根目录、`docs/` 根目录或零散位置创建单视频文件。

### 日期级索引

每个日期只保留一个当日视频清单：

```text
outputs/video/YYYY-MM-DD_保存清单.md
```

清单记录当天发现、保存、下载、转写、整理和复核的所有视频。

### 单视频任务包

每个视频使用稳定的 `{video_key}` 命名，来源于视频标题，去掉特殊符号并用下划线连接。示例：`程恒祥_大帅_5`。

单视频产物分散在固定日期目录下，不额外新建 docs 文档：

```text
data/video_transcripts/YYYY-MM-DD/{video_key}__full__medium__raw.txt
data/video_transcripts/YYYY-MM-DD/{video_key}__full__medium__corrected.txt
data/video_transcripts/YYYY-MM-DD/{video_key}__full__medium__segments.json

data/video_structured/YYYY-MM-DD/{video_key}__opinions.json
data/video_structured/YYYY-MM-DD/{video_key}__visual_review_candidates.json
data/video_structured/YYYY-MM-DD/{video_key}__visual_review_results.json

data/video_frames/YYYY-MM-DD/{video_key}/
outputs/video/YYYY-MM-DD_{video_key}_视频观点整理.md
```

本地视频本体放在：

```text
data/video_files/YYYY-MM-DD/
```

`data/video_files/` 默认不进 Git。截帧、转写、结构化 JSON 和整理稿可以进入 Git，用于后续回溯证据链。

## 工具与职责

| 工具 | 负责的操作 | 主要输入 | 主要输出 | 是否消耗 Codex token |
| --- | --- | --- | --- | --- |
| Chrome | 读取 Fanbook `#视频` 消息、打开夸克分享页、确认保存结果 | Fanbook 和夸克网页 | 链接、文件信息、保存状态 | 页面内容进入模型判断时会少量消耗 |
| 夸克网页/客户端 | 保存云端视频、把视频下载到本地 | 夸克分享链接或网盘文件 | 本地 `.mp4`、下载记录 | 不消耗，主要是网络和磁盘 |
| `ffprobe` | 读取视频时长、分辨率、音视频流和文件信息 | 本地视频 | 视频元信息 | 不消耗 |
| `ffmpeg` | 抽取 16kHz 单声道 WAV、按时间点抽帧、拼接 contact sheet | 本地视频、复核时间点 | 临时 WAV、JPG/PNG 截帧、contact sheet | 不消耗，主要是本地算力 |
| `scripts/video_transcribe.py` | 串联 `ffmpeg`、faster-whisper 和词表纠错，统一生成转写文件 | 本地视频、日期、`video_key` | raw/corrected 文本、segments JSON | 不消耗 |
| faster-whisper `medium` | 本地语音识别和时间分段 | 16kHz WAV | 带时间戳的转写分段 | 不消耗，主要是本地算力和模型加载时间 |
| `data/video_terms_corrections.json` | 修正高频财经专名误识别 | 原始转写文本 | 纠错转写文本 | 不消耗 |
| Codex/语言模型 | 阅读纠错稿、按主题拆观点、生成复核候选和最终整理稿 | corrected 文本、历史框架、复核结果 | opinions JSON、候选 JSON、Markdown 整理稿 | **消耗，长转写稿是主要 token 来源** |
| 本地 OCR / 人工画面复核 | 核对股票名、数字、表格和图表结论 | 关键截帧 | visual review results JSON | OCR 不消耗；截图交给模型查看时会消耗视觉 token |
| `json.tool`、`wc`、`git diff --check` | 校验 JSON、转写行数和提交格式 | 已生成文件 | 校验结果 | 不消耗 |

其中最主要的 token 消耗发生在“读取长转写稿并整理观点”和“查看关键截图并复核画面”两步。视频转码、音频抽取、faster-whisper 转写、文件校验都在本地执行，不使用 Codex token。

## 网盘保存步骤

1. 读取 `state/video_checkpoint.json`，确认上一轮视频断点。
2. 使用 Chrome 打开 Fanbook `#视频` 频道。
3. 从顶部开始识别新增消息，扫到上一轮断点停止。
4. 只处理 `https://pan.quark.cn/s/` 开头的夸克链接。
5. 腾讯会议、其他网盘或非视频链接只记录，不执行保存。
6. 打开夸克分享页，确认文件名、大小、修改时间。
7. 在分享页底部先点 `转存至`，选择 `全部文件/格隆汇/YY.M.DD`。
8. 确认页面底部目标已变成目标目录后，再点 `保存到网盘`。
9. 页面出现 `保存成功` 且 `已保存至：YY.M.DD` 后，才记录为 `saved_to_target`。

## 本地下载步骤

当用户要求“把视频下到本地”时，和网盘保存分开处理：

1. 先确认视频已经在夸克网盘目标日期目录里。
2. 优先尝试网页下载；如果网页下载无响应、账号提示异常或无法触发浏览器下载，则改用夸克客户端。
3. 在夸克客户端进入 `全部文件/格隆汇/YY.M.DD`，选中目标视频并执行下载。
4. 下载路径选择 `data/video_files/YYYY-MM-DD/`。
5. 等待 `.qkdownloading` 临时文件消失，正式 `.mp4` 出现后，才记录为 `downloaded`。
6. 同步写入 `data/video_downloads/YYYY-MM-DD.jsonl`，记录云端文件名、本地文件名、来源链接、目标路径、大小和下载方式。

## 音频转写步骤

当用户确认开始整理视频内容时，第一步先做音频转写，不直接进入观点拆解：

1. 默认使用 `scripts/video_transcribe.py` 和 faster-whisper `medium` 模型。
2. 从本地视频抽取 16kHz 单声道 WAV，临时音频放在 `tmp/video_transcribe/`。
3. 输出原始转写、词表纠错后的转写、结构化分段 JSON 到 `data/video_transcripts/YYYY-MM-DD/`。
4. 纠错词表放在 `data/video_terms_corrections.json`，用于修正高频财经专名误识别。
5. 后续观点拆解优先使用 `__corrected.txt`，但原始转写必须保留，方便回看 ASR 原貌。

## 观点拆解与画面复核步骤

音频转写完成后，先走“文字主线”，再按需看画面：

1. 读取 `data/video_transcripts/YYYY-MM-DD/*__corrected.txt`。
2. 按主题拆成结构化观点，输出到 `data/video_structured/YYYY-MM-DD/*__opinions.json`。
3. 同步生成可读整理稿到 `outputs/video/`，标题使用视频日期和视频名。
4. 对以下内容不要直接写成最终强结论，必须进入画面复核候选：
   - 讲者明确说“图里”“屏幕上”“我这里列出”。
   - 股票名、ETF名、行业名被 ASR 识别得不稳定。
   - 目标价、仓位比例、涨跌幅、市值、时间窗口等关键数字密集。
   - 图表结论依赖走势、表格、截图或屏幕标注。
5. 画面复核候选输出到 `data/video_structured/YYYY-MM-DD/*__visual_review_candidates.json`。
6. 按候选时间点从本地视频抽帧，素材放入 `data/video_frames/YYYY-MM-DD/{video_key}/`。
7. 先尝试本地 OCR；若 OCR 对截帧失败，则人工读取画面并在复核结果里记录原因。
8. 画面复核结果输出到 `data/video_structured/YYYY-MM-DD/*__visual_review_results.json`。
9. 未完成画面复核前，整理稿状态写为 `audio_summarized_needs_visual_review`；部分候选完成但仍有音频待确认时，状态写为 `visual_reviewed_partial`；全部候选闭环后才写为 `visual_reviewed`。

## 状态机

每个视频按以下状态推进，不跳级：

```text
found_in_fanbook
  -> saved_to_target
  -> downloaded
  -> transcribed
  -> audio_summarized_needs_visual_review
  -> visual_reviewed_partial
  -> visual_reviewed
```

说明：

- `saved_to_target`：夸克显示保存成功且目标目录正确。
- `downloaded`：本地 `.mp4` 已出现，`.qkdownloading` 消失。
- `transcribed`：原始转写、纠错转写、segments JSON 都生成。
- `audio_summarized_needs_visual_review`：已有音频版观点整理，但图表、股票名、数字仍待画面复核。
- `visual_reviewed_partial`：已完成部分画面复核，但仍有画面未显示或只能按音频保留的待确认项。
- `visual_reviewed`：所有候选复核闭环，强观点可以进入正式整理。

## 记录输出

每轮同步更新：

- `data/video_links/YYYY-MM-DD.jsonl`
- `data/video_downloads/YYYY-MM-DD.jsonl`
- `data/video_transcripts/YYYY-MM-DD/*`
- `data/video_structured/YYYY-MM-DD/*`
- `data/video_frames/YYYY-MM-DD/{video_key}/`
- `outputs/video/YYYY-MM-DD_保存清单.md`
- `outputs/video/YYYY-MM-DD_*_视频观点整理.md`
- `state/video_checkpoint.json`
- `docs/视频版本/操作日志.md`

## 异常处理

- 如果页面直接保存到默认 `来自：分享`，不要当作完成；需要重新选择目标目录后再保存一次，或经用户确认后移动文件。
- 如果夸克提示账号异常，但最终仍显示 `保存成功`，以最终保存弹窗和目标目录为准，同时在记录里写明异常提示。
- 如果目标日期文件夹不存在，先提示用户确认是否新建；新建属于云端文件管理动作。
- 如果本地文件仍带 `.qkdownloading` 后缀，不算下载完成；继续等待或记录为 `downloading`。
