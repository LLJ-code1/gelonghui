# 断点规则

## 目标

Fanbook 圈子帖子外层没有稳定发布日期，因此不能依赖页面日期排序做增量。断点用于判断“上次已经看到哪里”，下一轮只处理断点以上的新内容。

## 断点对象

断点记录本轮最顶部帖子，而不是本轮最后处理的帖子。

建议字段：

```json
{
  "checkpoint_version": 1,
  "updated_at": "2026-05-14T21:00:00+08:00",
  "collection_date": "2026-05-14",
  "batch_id": "2026-05-14_2100",
  "top_item": {
    "source_position": 1,
    "outer_author": "周阳",
    "inner_author": "恒亦",
    "inner_date_text": "5月14",
    "title": "盘前思路",
    "image_hash": "sha256:example-image-hash",
    "ocr_fingerprint": "fp:example-ocr-fingerprint"
  }
}
```

## 匹配优先级

判断某条帖子是否是上一轮断点时，按以下顺序匹配：

1. `image_hash`
2. `ocr_fingerprint`
3. `outer_author + inner_author + inner_date_text + title`
4. `outer_author + title + source_position`，仅作为弱匹配，需要复核

## 运行流程

1. 读取上一轮 `state/checkpoint.json`。
2. 打开 `最新` 流。
3. 从顶部开始逐条处理。
4. 遇到上一轮 `top_item`，停止。
5. 未遇到断点时，最多向下扫到预设屏数或条数，并标记 `checkpoint_missing`。
6. 本轮结束后，把本轮顶部帖子写入新的 `top_item`。

## 首次无断点流程

首次采集没有 `state/checkpoint.json`，需要使用临时停止线。

规则：

1. 以运行日期为准计算昨天日期。
2. 从 `最新` 流顶部开始。
3. 对每条帖子识别截图内部日期。
4. 如果截图内部明确出现昨天日期，停止本轮采集。
5. 停止线所在帖子不纳入本轮新增，除非它上方还有同一天需要处理的内容无法分离。
6. 本轮结束后仍然把本轮最顶部帖子写成新的 checkpoint。

日期匹配示例：

```text
运行日期：2026-05-14
昨天日期：2026-05-13
可匹配文本：5月13日 / 5月13 / 2026-05-13 / 20260513
```

如果截图内部没有日期，不能作为停止线，继续向下识别。

## 特殊情况

### 顶部没有变化

如果当前顶部帖子等于上一轮断点：

- 本轮无新增内容。
- 仍记录一次操作日志。
- 不更新日报正文，或只写 `本轮无新增`。

### 断点消失

如果上一轮断点被删除、排序变化或页面懒加载失败：

- 不要把所有可见内容都当作新增。
- 继续向下扫有限范围。
- 使用去重库 `state/seen_items.json` 辅助判断。
- 在操作日志中记录 `checkpoint_missing`。

### 同一张图被多次转发

如果 `image_hash` 或 `ocr_fingerprint` 重复：

- 标记为 `duplicate`。
- 保留本轮出现记录。
- 日报中不重复总结。

### 截图内日期缺失

如果截图内没有日期：

- `inner_date_text` 填 `未识别`。
- 仍按采集日期归档。
- 如果观点重要，标记 `needs_review`。
