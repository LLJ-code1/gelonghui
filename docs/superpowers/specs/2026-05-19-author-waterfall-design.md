# 作者观点瀑布流设计

## 背景

当前项目已经形成了三类输出：

- `data/structured/YYYY-MM-DD/items.jsonl`：单条帖子结构化记录。
- `outputs/daily/YYYY-MM-DD_观点汇总.md`：按天看的全局日报。
- `outputs/authors/作者.md`：按作者列出帖子简述。

现有作者文件更像“帖子索引”，不足以回答这些问题：

- 某个作者今天具体关注什么？
- 他看好和谨慎的方向分别是什么？
- 他的观点相比上一轮有没有变化？
- 有哪些后续跟踪点？

因此新增“作者观点瀑布流”输出，让每个作者文件成为可连续阅读的观点时间线。

## 目标

把每轮采集后的作者归档升级为“作者每日观点日志”。

用户打开 `outputs/authors/王炽.md` 这类文件时，应能直接看到：

- 作者长期画像。
- 最新状态。
- 每天的观点快照。
- 每天关注、看好、谨慎、操作含义、待跟踪点。
- 原始素材索引和复核状态。

## 非目标

- 不替代日报。日报仍负责“今天全市场/全作者在说什么”。
- 不替代原始结构化记录。`items.jsonl` 仍是单条素材源。
- 不对 `needs_review` 内容强行生成确定观点。
- 不新增复杂前端或数据库，先保持 Markdown + JSONL 的本地文件体系。

## 输出层级

推荐形成四层：

```text
data/structured/YYYY-MM-DD/items.jsonl
  -> 单条帖子事实层

data/author_daily/YYYY-MM-DD.jsonl
  -> 按作者聚合的每日观点快照

outputs/daily/YYYY-MM-DD_观点汇总.md
  -> 当天全局日报

outputs/authors/作者.md
  -> 单个作者长期观点瀑布流
```

## 新增目录

```text
data/author_daily/
templates/author_daily_record_template.json
```

`data/author_daily/YYYY-MM-DD.jsonl` 一行代表一个作者在某一天的一份观点快照。

## 作者每日快照字段

建议字段如下：

```json
{
  "author": "王炽",
  "date": "2026-05-19",
  "batch_ids": ["2026-05-19_1034"],
  "item_ids": ["2026-05-19_1034_005"],
  "source_status": "summarized",
  "confidence": "high",
  "today_conclusion": "市场进入震荡阶段，量能不过分萎缩时仍有轮动机会。",
  "focus": ["CPO", "OCS", "硅光", "英伟达财报"],
  "bullish": ["有产业节点催化的光通信方向"],
  "cautious": ["高位追涨", "缺少事件验证的科技题材"],
  "operation": ["降低追高", "控仓低吸", "等产业节点确认"],
  "change_vs_previous": "延续前一轮科技分化判断，但更强调震荡和低吸节奏。",
  "watchlist": ["英伟达财报后光通信链反馈", "OCS/硅光产业节点是否继续发酵"],
  "raw_evidence": [
    {
      "item_id": "2026-05-19_1034_005",
      "ocr_text_path": "data/ocr/2026-05-19/2026-05-19_1034_005.txt",
      "raw_image_paths": ["data/raw/2026-05-19/2026-05-19_1034_screen_001_D1.png"]

```

## 作者 Markdown 模板

`outputs/authors/作者.md` 升级为以下结构：

```markdown
# 王炽观点瀑布流

## 作者画像

- 长期关注：
- 风格：
- 常见判断维度：
- 主要风险：

## 最新状态

- 当前主线：
- 最近变化：
- 当前风险：
- 下一步跟踪：

## 观点时间线

### 2026-05-19

#### 今日结论

#### 关注什么

#### 看好什么

#### 不看好/谨慎什么

#### 操作含义

#### 相比上一轮变化

#### 待跟踪

#### 原始素材
```

最新日期放在最上方，历史日期向下排列。

## 数据生成规则

每轮 `整理一下最新观点` 后，流程变为：

1. 正常采集 Fanbook `最新` 流，写入 `items.jsonl`。
2. 按 `summary_author` 分组。
3. 对每个作者当日新增 item 做聚合。
4. 只把 `summarized` 条目写入强观点字段。
5. `needs_review` 条目只进入“待复核素材”或 `review_note`，不能写成确定性观点。
6. 生成或追加 `data/author_daily/YYYY-MM-DD.jsonl`。
7. 根据 `author_daily` 重新渲染或追加 `outputs/authors/作者.md`。
8. 更新 `docs/操作日志.md`，记录本轮作者瀑布流生成情况。

## 作者画像维护

作者画像不是每天重写，而是随时间沉淀。

建议初始规则：

- 第一次出现作者时，生成一个简短画像，标记为 `待沉淀`。
- 当某作者连续多日重复出现主题后，再补充长期关注和风格。
- 不确定的画像不要强写，统一写 `待确认`。

示例：

```markdown
## 作者画像

- 长期关注：CPO、OCS、硅光、科技分化（待继续验证）
- 风格：偏交易节奏 + 产业催化
- 常见判断维度：市场阶段、量能、事件催化、仓位
- 主要风险：高位追涨、产业节点不及预期
```

## 状态与置信度

作者每日快照使用两个状态维度：

- `source_status`：来自原 item 的整体状态，优先级为 `needs_review > summarized`。
- `confidence`：作者快照可转述置信度，建议值为 `high`、`medium`、`low`。

规则：

- 只要该作者当日核心内容未打开详情或长图未复核，`confidence` 不得为 `high`。
- 如果全部关键条目是 `needs_review`，作者当日只写“可确认主题”和“待复核”，不写强结论。
- 如果部分条目 `summarized`、部分条目 `needs_review`，强观点只来自 `summarized`，待复核内容单列。

## 与现有作者归档的关系

现有 `outputs/authors/*.md` 不另建新路径，直接升级。

好处：

- 用户仍然点同一个作者文件。
- 历史索引不丢。
- 后续可以逐步把旧日期补成新模板，不需要一次性重构所有历史。

迁移策略：

1. 先对新增采集日使用新模板。
2. 对已有历史，只保留原简述作为“历史素材索引”。
3. 当用户点名某个作者时，再回补该作者历史日期的详细瀑布流。

## 触发规则

`整理一下最新观点` 的默认产物扩展为：

- 全局日报。
- 作者观点瀑布流更新。
- 作者每日快照 JSONL。
- 操作日志和 checkpoint。

新增可选触发词：

- `展开王炽的详细观点`：针对单个作者生成或补全详细瀑布流。
- `看一下 herry 最近观点变化`：按日期比较该作者观点变化。
- `回补周阳历史观点瀑布流`：从已有历史素材回补作者时间线。

## 验收标准

第一版完成后，应满足：

- 新增 `data/author_daily/YYYY-MM-DD.jsonl`。
- 至少能用 2026-05-19 的数据生成 `王炽`、`周阳`、`herry` 三个作者的瀑布流样例。
- 作者文件最新日期在最上方。
- `needs_review` 不会被写成强观点。
- 每个作者日期块都能追溯到 `item_id`。
- `git diff --check`、JSONL 解析检查通过。

## 风险与处理

- 风险：作者文件越来越长。
  - 处理：先保留单文件瀑布流；如果后续过长，再拆 `outputs/authors/作者/YYYY-MM.md`。
- 风险：作者画像过早定型。
  - 处理：初期多用 `待确认`，只在多日重复出现后沉淀长期画像。
- 风险：低置信度内容污染强观点。
  - 处理：`needs_review` 只能进入待复核素材，不进入“看好/不看好/操作含义”强字段。
