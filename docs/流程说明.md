# Fanbook 圈子观点采集流程

## 1. 基本原则

本项目不以帖子内截图日期作为归档依据，而以实际采集日期作为归档依据。

示例：

- `2026-05-14` 早上跑一次，归入 `2026-05-14`。
- `2026-05-14` 晚上再跑一次，也归入 `2026-05-14`。
- `2026-05-15` 再跑，则归入 `2026-05-15`。

截图里如果写着 `5月14`，只记录为内容内日期，不决定文件放到哪一天。

## 2. 每轮采集入口

固定入口：

```text
https://web.fanbook.cn/channels/887510463079116800/circle?sort=publish
```

页面选择：

- 进入 Fanbook 频道。
- 点击 `圈子`。
- 切到 `最新`。
- 从页面顶部第一个帖子开始处理。

## 3. 断点逻辑

每轮采集开始时，读取上一轮 `state/checkpoint.json`。

处理顺序：

1. 从 `最新` 流顶部开始向下扫。
2. 对每个帖子生成一个候选指纹。
3. 如果遇到上一轮断点，停止扫描。
4. 断点以上的帖子视为本轮新增。
5. 本轮结束后，把本轮最顶部帖子写成新的断点。

如果本轮顶部帖子和上一轮断点相同，说明没有新增。

## 4. 首次采集规则

如果项目还没有 `state/checkpoint.json`，第一轮没有历史断点，不能简单把页面所有内容都当作新增。

首次采集使用临时停止线：

- 从 `最新` 流顶部开始识别。
- 一路向下处理可见帖子。
- 当截图内部明确出现昨天日期时停止。
- 截图无日期、日期识别不清、只有外层页面信息时，不作为停止条件。

示例：

- 运行日期是 `2026-05-14`。
- 昨天日期是 `2026-05-13`，常见写法包括 `5月13日`、`2026-05-13`、`20260513`。
- 第一轮采集从顶部开始，识别到截图内部首次出现这些日期后停止。
- 已处理内容统一归入 `2026-05-14`，即使截图内部写的是 `5月14` 或没有日期。

## 5. 每条内容保存什么

每条帖子至少保存：

- 采集日期和批次
- 页面外层作者
- 截图内作者
- 截图内日期
- 标题或首行
- 市场分类
- 原始截图路径
- OCR 文本路径
- 图片 hash
- OCR 指纹
- 是否重复
- 处理状态

## 6. 批次命名

批次建议使用：

```text
YYYY-MM-DD_AM
YYYY-MM-DD_PM
YYYY-MM-DD_HHMM
```

如果一天多次采集，优先用 `YYYY-MM-DD_HHMM`，避免上午/晚上不够精确。

## 7. 输出层

每轮采集完成后同步生成两类结果：

1. 素材留存
   - 原始截图：`data/raw/YYYY-MM-DD/`
   - OCR 文本：`data/ocr/YYYY-MM-DD/`
   - 结构化记录：`data/structured/YYYY-MM-DD/`

2. 观点输出
   - 每日汇总：`outputs/daily/YYYY-MM-DD_观点汇总.md`
   - 作者归档：`outputs/authors/作者名.md`

## 8. 日报结构

日报建议结构：

```text
# YYYY-MM-DD 观点汇总

## 今日采集

## 今日主线

## 按市场分类

## 按作者汇总

## 共识观点

## 冲突观点

## 可转述话术

## 原始素材索引
```

## 9. 异常处理

- 登录失效：停止采集，记录到 `docs/操作日志.md`，等待手动登录。
- 找不到上一轮断点：继续向下扫一段，记录为 `checkpoint_missing`，不要强行判定全部是新增。
- 首次采集无断点：用截图内昨天日期作为停止线，并在日志中记录 `initial_stop_by_yesterday_inner_date`。
- OCR 失败：保留原图，状态标记为 `ocr_failed`。
- 截图内无日期：`inner_date_text` 记为 `未识别`。
- 作者不一致：外层作者和截图内作者都保留，后续汇总优先用截图内作者表达观点来源。
