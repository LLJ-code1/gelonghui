# Fanbook 圈子观点采集流程

## 0. 用户触发词

当用户说以下任一句时，默认启动本流程：

- `整理一下最新观点`
- `整理一下最新的观点`
- `整理最新观点`
- `更新最新观点`
- `跑一轮最新观点`

默认动作是打开 Fanbook 圈子 `最新` 流，从顶部开始按 `state/checkpoint.json` 增量采集，扫到上一轮断点停止。

不要把这些话理解成“只整理本地已有日报”或“补一份精简版”。只有用户明确说“只看本地已有内容”或“不要打开 Fanbook”时，才改成本地整理。

## 1. 基本原则

本项目不以帖子内截图日期作为归档依据，而以实际采集日期作为归档依据。

示例：

- `2026-05-14` 早上跑一次，归入 `2026-05-14`。
- `2026-05-14` 晚上再跑一次，也归入 `2026-05-14`。
- `2026-05-15` 再跑，则归入 `2026-05-15`。

截图里如果写着 `5月14`，只记录为内容内日期，不决定文件放到哪一天。

## 2. 每轮采集入口

固定入口：

```text
https://web.fanbook.cn/channels/887510463079116800/circle?sort=publish
```

页面选择：

- 进入 Fanbook 频道。
- 点击 `圈子`。
- 切到 `最新`。
- 从页面顶部第一个帖子开始处理。

## 3. 断点逻辑

每轮采集开始时，读取上一轮 `state/checkpoint.json`。

处理顺序：

1. 从 `最新` 流顶部开始向下扫。
2. 对每个帖子生成一个候选指纹。
3. 如果遇到上一轮断点，停止扫描。
4. 断点以上的帖子视为本轮新增。
5. 本轮结束后，把本轮最顶部帖子写成新的断点。

如果本轮顶部帖子和上一轮断点相同，说明没有新增。

## 4. 首次采集规则

如果项目还没有 `state/checkpoint.json`，第一轮没有历史断点，不能简单把页面所有内容都当作新增。

首次采集使用临时停止线：

- 从 `最新` 流顶部开始识别。
- 一路向下处理可见帖子。
- 当截图内部明确出现昨天日期时停止。
- 截图无日期、日期识别不清、只有外层页面信息时，不作为停止条件。

示例：

- 运行日期是 `2026-05-14`。
- 昨天日期是 `2026-05-13`，常见写法包括 `5月13日`、`2026-05-13`、`20260513`。
- 第一轮采集从顶部开始，识别到截图内部首次出现这些日期后停止。
- 已处理内容统一归入 `2026-05-14`，即使截图内部写的是 `5月14` 或没有日期。

## 5. 每条内容保存什么

每条帖子至少保存：

- 采集日期和批次
- 页面外层作者
- 截图内作者
- 汇总作者
- 截图内日期
- 标题或首行
- 市场分类
- 原始截图路径
- OCR 文本路径
- 图片 hash
- OCR 指纹
- 是否重复
- 处理状态

## 6. 单帖整理流程

以 `大帅 / 阿里2601业绩` 这类帖子为例，单条内容按下面顺序整理：

1. 先确认外层发帖人
   - 看 Fanbook 卡片底部或点开大图右侧信息区。
   - 外层发帖人写入 `outer_author`。
   - `summary_author` 固定等于 `outer_author`。
   - 如果外层只露出一部分或看不清，先点开大图确认，不直接入库。

2. 再识别截图内来源
   - 截图顶部的账号、团队、栏目写入 `inner_author`。
   - 截图内来源只做元数据，不决定作者归档。
   - 例如外层是 `大帅`，截图内来源是 `研究企业罗大帅`，归档仍然是 `大帅`。

3. 提取内容信息
   - 记录截图内日期到 `inner_date_text`。
   - 提取标题或首行到 `title`。
   - 摘出关键数据、判断和风险提示。
   - 对看不全、多图、文字太小的内容标记 `needs_review`。
   - 如果是长图、密集文字图或首屏缩略图，不允许只用列表卡片摘要直接生成强观点；必须点开原图或详情图复核正文后，才能把状态从 `needs_review` 提升为 `summarized`。
   - 如果只完成列表截图 OCR，摘要只能写“可确认主题”和“待复核原因”，不能压缩成确定性观点。

4. 打标签
   - `market_tags` 记录市场，例如 `中概股`、`港股`、`美股`。
   - `topic_tags` 记录主题，例如 `阿里`、`业绩`、`云计算`、`现金流`。

5. 写结构化记录
   - 一条帖子写入 `data/structured/YYYY-MM-DD/items.jsonl` 一行。
   - 保留原始截图路径、OCR 文本路径、图片 hash、OCR 指纹。
   - 摘要用外层作者表述，例如“`大帅` 这条阿里2601业绩认为……”。

6. 同步输出
   - 日报按 `summary_author` 放入“按作者汇总”。
   - 作者归档写入 `outputs/authors/大帅.md`。
   - 原始素材索引同时保留 `汇总作者` 和 `截图内来源`。

7. 复核要求
   - 如果作者、标题或正文是从局部截图推断出来的，必须标记 `needs_review`。
   - 后续点开大图确认后，如果发现误识别，要同步修正 JSONL、日报、作者归档和操作日志。

## 7. 批次命名

批次建议使用：

```text
YYYY-MM-DD_AM
YYYY-MM-DD_PM
YYYY-MM-DD_HHMM
```

如果一天多次采集，优先用 `YYYY-MM-DD_HHMM`，避免上午/晚上不够精确。

## 8. 输出层

每轮采集完成后同步生成两类结果：

1. 素材留存
   - 原始截图：`data/raw/YYYY-MM-DD/`
   - OCR 文本：`data/ocr/YYYY-MM-DD/`
   - 结构化记录：`data/structured/YYYY-MM-DD/`
   - 作者每日快照：`data/author_daily/YYYY-MM-DD.jsonl`

2. 观点输出
   - 每日汇总：`outputs/daily/YYYY-MM-DD_观点汇总.md`
   - 作者观点瀑布流：`outputs/authors/作者名.md`

## 9. 日报结构

日报建议结构：

```text
# YYYY-MM-DD 观点汇总

## 今日采集

## 今日主线

## 按市场分类

## 按作者汇总

## 共识观点

## 冲突观点

## 可转述话术

## 原始素材索引
```

## 10. 异常处理

- 登录失效：停止采集，记录到 `docs/操作日志.md`，等待手动登录。
- 找不到上一轮断点：继续向下扫一段，记录为 `checkpoint_missing`，不要强行判定全部是新增。
- 首次采集无断点：用截图内昨天日期作为停止线，并在日志中记录 `initial_stop_by_yesterday_inner_date`。
- OCR 失败：保留原图，状态标记为 `ocr_failed`。
- 截图内无日期：`inner_date_text` 记为 `未识别`。
- 作者不一致：外层作者和截图内作者都保留，日报和作者归档按外层作者汇总，截图内作者只作为来源备注。
